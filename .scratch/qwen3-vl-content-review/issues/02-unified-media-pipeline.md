# 02 — 贯通统一静态图片与 GIF 媒体管线

**What to build:** 用真实、确定性的媒体处理替换端到端骨架中的媒体占位实现，使静态图片与 GIF 都能按已确认的动态分辨率和帧序语义进入同一 actor 调用链，并继续得到最终 R5 结果。

**Blocked by:** 01 — 建立可执行的端到端契约骨架

**Status:** ready-for-agent

- [ ] 静态图片作为单个 image 输入，并在 1,024 视觉 token、1,048,576 像素上限内保留完整画面和宽高比。
- [ ] 超限静态图片只进行确定性等比例缩小，不裁剪、不拉伸。
- [ ] 1～4 帧 GIF 使用全部帧且不补帧；超过 4 帧时按累计播放时间的 0、1/3、2/3、1 位置确定性选取 4 帧。
- [ ] GIF 帧作为一个有序 video 帧列表进入 actor，每帧遵守 256 视觉 token、262,144 像素上限。
- [ ] 相同媒体和相同媒体管线版本重复处理会得到相同帧序、尺寸和预处理摘要。
- [ ] 超宽、超高、超大静态图及 1、2、3、4、5 帧和可变帧时长 GIF 均有自动化测试。
- [ ] 静态图和 GIF 都能继续贯通严格解析与 R5 最终结果，而不建立两套业务链路。
